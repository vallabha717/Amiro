This walkthrough takes you from nothing to your first conversation in a few
minutes. Amiro sets itself up the first time you open it. There is no default
password and no sign-up: the first account you create is the owner, and it is
the only account. You can skip steps and finish them later.

## Step 1: Install and open Amiro

Choose the shape that fits you.

<Tabs>
<Tab title="Desktop app">
Download and open the Amiro desktop app for your platform. It runs everything
on your own computer and needs nothing else installed.

When it opens, it starts its own copy of the app on a private local address, so
you do not have to think about ports or servers.
</Tab>
<Tab title="On a server or VM">
Install the server on Linux or macOS with one command:

```bash
curl -fsSL https://github.com/vallabha717/Amiro/releases/latest/download/install.sh | bash
```

To reach it from other machines on your network, add `--public`:

```bash
curl -fsSL https://github.com/vallabha717/Amiro/releases/latest/download/install.sh | bash -s -- --public
```

The installer downloads the right build for your operating system and CPU,
checks it, sets it up under `~/.amiro`, writes a starter `amiro.toml`, and starts
the server. It prints the address to open, so use that rather than guessing a
port. Afterwards, `amiro status`, `amiro start`, and `amiro restart` manage it,
and `amiro help` lists the rest.
</Tab>
</Tabs>

<Note>
On a network-reachable install, put TLS and a network boundary in front of Amiro
before treating it as public. The owner sign-in protects the API, but plain HTTP
on an open network is not enough.
</Note>

## Step 2: Create the owner account

On a fresh install, opening Amiro lands on the welcome screen. Click **Get
started** and fill in:

- **What should your agent call you?** Your first name is fine.
- **Email or username.** Matched case-insensitively when you sign in.
- **Password** and **Confirm password.** At least 12 characters, with a letter
  plus a number or symbol. **Create account** stays disabled until both match.

<Warning>
This is the only required step, and there is no password recovery by email.
Store the password somewhere safe. If you lose it, reset it on the machine
running Amiro (see below).
</Warning>

## Step 3: The setup chat

Amiro now introduces itself and sets itself up as a conversation: it streams
one question at a time, you answer with a card, and a progress line shows
**Step N of 8**. On the right, the story panel explains each chapter; on the
left, your agent's face and every answer so far.

<Steps>
<Step title="Let's go → Look">
Pick one of four plush shapes (Headphones, Sprout, Starfish, Dreamer) and one
of nine colours, then **That's me**. The sidebar theme follows the colour. The
main agent is always called Amiro; agents you add in [Team](/using/team) get
their own names.
</Step>
<Step title="Default prompt">
Read exactly what the agent works from: the `IDENTITY.md` and `SOUL.md` tabs.
You can edit both later in **Agent → Workspace**.
</Step>
<Step title="Personality">
Pick a preset such as **Warm Companion** or **Sharp Operator**. The dials
behind it are on **Agent → Personality**.
</Step>
<Step title="Brain (AI provider)">
The whole provider catalog is listed. Type to search (for example *OpenCode
Go*), pick it, paste its API key into the masked field and click **Save key**.
**Continue** unlocks once the provider is connected. OAuth and device-code
sign-ins and local OpenAI-compatible endpoints use the same card.

<Note>
The key goes straight to the encrypted vault (`~/.amiro/protected/`). It is
never shown back and never becomes a chat message.
</Note>
</Step>
<Step title="Web search">
**Bing** and **DuckDuckGo** need no key and work at once from a home
connection (on a cloud VM they often get a challenge page and no results, so
use a keyed engine there).
Brave, Tavily, Exa, Serper and
Firecrawl ask for a key in a password field; SearXNG takes your instance URL.
</Step>
<Step title="Connectors">
Paste a Composio key for 1,000+ apps, or **Add server** for an MCP server (a remote URL
or a local command). Easy to do later from [Connectors](/using/connectors).
</Step>
<Step title="Voice and listening">
Choose a speaking voice (OpenAI, ElevenLabs, Deepgram… or the browser's own)
and how Amiro listens. Live voice works with any keyed provider; the
browser's built-in engines cover read-aloud and dictation only.
</Step>
<Step title="Summary">
What is done and what is left for later. **Start working with Amiro** opens
**Team** with Amiro as the first card; open it to start chatting.
</Step>
</Steps>

Then pick the default model in **Admin → Models & Providers** (**Set default**
on the provider card) and run a model test:

- Each skipped step leaves a reminder card at the bottom of the sidebar that
  links straight to it. It disappears once the step is done.
- Run the whole setup chat again any time from **Admin → General**.

## Step 4: Sign in from then on

Once the owner exists, Amiro shows a sign-in page. Your login can be an email or
a username, matched case-insensitively. See
[Your account](/settings/account) for changing your email or password and for
what single-owner means.

## If you forget the password

Amiro has no email recovery because it runs on your machine. Reset it on the
machine running Amiro:

```bash
amiro reset-password                  # packaged server install (install.sh)
amiro-backend reset-password          # from a source checkout; asks twice
amiro-backend reset-password --login you@example.com   # also change the login
```

This signs out every session, so sign in again afterwards. In the desktop app,
the backend binary sits next to the app:

| OS | Command |
| --- | --- |
| macOS | `/Applications/Amiro.app/Contents/MacOS/backend reset-password` |
| Windows | `"C:\Program Files\Amiro\backend.exe" reset-password` |
| Linux (deb/rpm) | `/usr/bin/backend reset-password` |

## Setting up from files instead

Everything the wizard asks for also comes from files, which is how scripted or
headless installs are provisioned. Precedence is: environment variables, then
`.env` files, then `amiro.toml`. A file never overrides a variable that is
already set. To get a commented starter file:

```bash
amiro-backend init-config
```

This writes `~/.amiro/amiro.toml`. The main sections are `[server]` (host, port,
token), `[owner]` (email, password or password file, name, timezone), `[agent]`
(name, avatar, color), and `[providers]` (API keys). Prefer `password_file` over
`password`, so the secret is not sitting in the config file itself.

For a headless first start you can also export the owner before starting Amiro:

```bash
export AMIRO_OWNER_EMAIL=owner@example.com
export AMIRO_OWNER_PASSWORD='a-long-owner-password'
# or: export AMIRO_OWNER_PASSWORD_FILE=/run/secrets/amiro-owner-password
```

## Step 5: Ask something real

Open a new chat and try a task, not a test. A few that show what Amiro does
well (more on [Everyday tasks](/using/everyday-tasks)):

```text
Search the web and compare Obsidian, Logseq and Joplin for personal notes today. Give me a table and cite the pages you used.
```

```text
Read https://en.wikipedia.org/wiki/Pomodoro_Technique, summarise it in 5 bullets and save the notes to notes/pomodoro.md.
```

```text
Every weekday at 8:00 am, give me a morning brief: today's weather in my city and the top 3 tech headlines with links.
```
