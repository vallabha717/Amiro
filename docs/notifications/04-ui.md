# 04 — Bell UI

## What is wrong today

`notifications-bell.tsx` (~large single file) mixes feed, detail, filters,
and settings in one popover with ad-hoc styling. The redesign splits it and
adopts Vellum inbox patterns: quiet list rows, category markers, relative
time, unread-first ordering, and a detail view with actions.

## Target structure

| File | Owns |
|---|---|
| `components/notifications/notifications-bell.tsx` | Bell button with a red unread dot, the panel header, popover on desktop and bottom sheet on phones |
| `components/notifications/notifications-feed.tsx` | The list: rows, empty, loading and error states |
| `components/notifications/notification-detail.tsx` | One notification: header actions, markdown body, delivery state, footer links |
| `components/notifications/notifications-settings.tsx` | Toggles, quiet hours, and where notifications go outside Amiro (opened from the … menu) |
| `components/notifications/channel-delivery-status.tsx` | "Outside Amiro": each channel's readiness, linking to Channels or Contacts |
| `lib/notifications/presence.ts` | Tells the backend which chat this tab has on screen |
| `lib/notifications/thread-activity.ts` | Working / unseen / failed marks for the chat list |

## As built: Vellum's bell, ported

The panel follows Vellum's `notifications-bell*` components closely:

- **Header:** "Notifications", a count pill, an **Unread** toggle, and a
  **…** menu (mark all as read, browser notifications, send a test,
  settings, clear all). There are no category filter chips.
- **Opening** always starts on unread, so the panel answers "what's new?".
- **Rows:** an unread dot (green, grey once read), the title, and the
  relative time. Under it, one muted line: for a chat reply, the chat's name
  and the reply's first line as plain text (markdown never shows as
  symbols); for an approval still waiting, what it asks; otherwise the
  source. Waiting approvals sort first, then newest first. On a pointer
  device the time fades into read/unread and delete icons; on touch those
  live in the detail.
- **Detail:** back, the title, and read/delete icons in the header; the
  full message as markdown in a fixed 400px frame that scrolls; external
  delivery attempts with resend under it; a footer with the time on the left
  and **Go to conversation** / **Open schedule** on the right. Opening a row
  marks it read.
- **Empty:** a bell in a soft well and one line of explanation; with the
  Unread toggle on and everything read, just "No unread notifications".

## Chat replies and the chat list

A chat reply only reaches the Bell when the user was not watching that chat
when it finished (Vellum's web-presence rule). The tab reports which chat it
shows (`POST /api/notifications/presence`) when the chat changes, on focus
and visibility changes, and every minute while the user is active; a report
older than three minutes is ignored. Opening a chat marks its reply
notifications read.

The sidebar's chat rows carry Vellum's status mark: a pulsing dot while the
chat is working, a green dot for a reply that landed while the user was
away, and a red alert for a turn that failed while they were away
(`GET /api/thread-activity`, kept live by `thread_activity` stream events).

## Standards that apply

- Thin pages, logic in `components/notifications/`, API calls only in
  `lib/backend/` (`ui` skill).
- Every string in `messages/en.json` **and** `messages/hi.json`, same keys
  and `{placeholders}`; `pnpm check:i18n` in Phase 04 exit criteria.
- Theme tokens only (light + dark verified), `ui/*` primitives,
  `lucide-react` icons, `sonner` toasts.
- A11y: icon-only buttons get `aria-label`, list uses list semantics, one
  `h1`-equivalent heading in detail; keyboard reachable throughout.
- `data-testid`s: `notifications-bell`, `notifications-feed`,
  `notification-row-<id>`, `notification-detail`,
  `notifications-settings`, `channel-delivery-<channel>`.
