# 07 — CI and guardrails

There is no CI in this repo today — no `.github/workflows`, no Makefile,
no root test script wiring the Go module in. Phase 8 adds it. This
document is what Phase 8 builds toward.

## Jobs

| Job | Trigger | Selection | Budget |
|---|---|---|---|
| `lint` | every push | `go vet` · `biome` · `tsc --noEmit` · `amirotest config example --check` | 2 min |
| `unit` | every push | `go test ./...` in `backend-go` + `pnpm test` | 4 min |
| `smoke` | every push | `amirotest run --tag smoke` | 3 min |
| `full` | PR + main | `amirotest run --surface backend,tui,ui` | 12 min |
| `desktop` | PR touching `src-tauri/**` or nightly | `amirotest run --surface desktop` | 20 min |
| `live` | nightly | `amirotest run --live --tag smoke` | 10 min, cost-capped |
| `record-check` | weekly | `amirotest doctor --cassettes` | 1 min |

`smoke` runs on every push and gates nothing else — it is the fast "is it
broken at all" signal. `full` is the merge gate.

## Matrix

- **OS**: `ubuntu-latest` for everything; `macos-latest` and
  `windows-latest` for `full` on main and on PRs touching `cmd/`,
  `internal/config`, `internal/secrets`, or `src-tauri/`. Those four are
  where the platform-specific code actually is —
  `config.appDataDir()` branches per-GOOS, and `go-keyring` has three
  entirely different backends.
- **Database**: sqlite always; postgres as a second `full` shard, since
  `internal/db` supports both dialects and `tests/repository/dialect_test.go`
  already exists to prove they agree.
- **Browser**: chromium always; firefox and webkit nightly.

## Required settings in CI

```yaml
env:
  AMIRO_TEST_PROVIDERS_MODE: replay
  AMIRO_TEST_RUN_STRICTCASSETTES: "true"   # a cassette miss FAILS, never degrades silently
  AMIRO_TEST_RUN_RETRIES: "0"              # CI must not paper over flakes
  AMIRO_TEST_RUN_KEEPARTIFACTS: on-failure
  AMIRO_TEST_BACKEND_BINARY: ./bin/amiro-server   # prebuilt in an earlier step
```

`strictCassettes` and `retries: 0` are the two settings that keep the suite
honest. Local development gets one retry and graceful cassette fallback;
CI gets neither.

## Artifacts

On failure, upload `tests/logs/<run-id>/` as a build artifact, with videos
and DB snapshots included. The `summary.md` is also posted as a PR comment,
so the failure and its artifact paths are visible without downloading
anything.

## Flake policy

1. A test that fails intermittently is tagged `flaky` **with a linked
   issue** in the same PR that observes it. Tagged tests still run and still
   report; they do not fail the build.
2. `amirotest report --flaky` reads the last N runs' `summary.json` and
   lists tests whose pass/fail history is mixed — including tests *not*
   tagged `flaky`, which is how quarantine candidates get found.
3. A `flaky` tag older than 30 days is a CI warning. Quarantine is a
   holding pen, not a destination.
4. Retries are never the fix. A test that needs a retry to pass has a race,
   and the race is either in the test or in the product.

## Guardrails the suite enforces on itself

These are tests in `suites/meta/`, and they are the reason the system does
not rot:

| Guard | Fails when |
|---|---|
| Config drift | `config.example.yaml` no longer matches `defaults.go` |
| Route coverage | A route exists in `internal/httpserver/router.go` with no test in `suites/backend/` — the router is parsed and compared against the suite index |
| Secret leakage | Any configured secret's literal value appears anywhere in the produced log tree |
| Orphan processes | Any spawned process outlives its test, or any port stays bound after teardown |
| Artifact contract | A failed test did not produce the artifacts its surface promises (trace, cast, http log) |
| Runtime budget | The default run exceeds 10 minutes on the reference runner |
| Address uniqueness | Two tests resolve to the same address, or a feature directory has no tests |

Route coverage is the highest-value one. Amiro has ~120 routes and is
mostly agent-written; the failure mode is a route that exists and has
never been called by anything. Parsing `router.go` for its
`mux.Handle*("METHOD /path", ...)` calls and diffing against what
`harness/apiclient` actually exercised turns that from invisible into a
build failure.

## Cost control for the live job

- The live job runs only `smoke`-tagged tests.
- `providers/cost.json` is compared against a ceiling
  (`AMIRO_TEST_COST_CEILING_USD`, default `2.00`); exceeding it fails the
  job.
- Every live test carries a hard token cap so a runaway agent loop cannot
  spend indefinitely.
- Live failures open (or update) a single tracking issue rather than
  spamming — a provider outage should not produce seven notifications.
