## Evidence from the completed UI integration

- The production Next.js static export built successfully with 38 pages. The running Rust backend serves `out/` and the API together on port 3000 via an explicit `AMIRO_PORT=3000` deployment override. The backend's source default is 8787.
- At the UI integration checkpoint, 646 frontend tests and typecheck passed. Test counts are dated observations, not release invariants.
- Chromium checked all four settings routes on desktop and mobile with no JavaScript errors or horizontal document overflow.
- The committed isolated browser workflow verified credential creation, masked metadata, persistence/reload, delete cancellation and confirmation; file preview matching the public API and read-only enforcement; memory pagination from 24 to 35 entries, search beyond the initial page and detail focus/Escape; and populated skill filtering and editor navigation.
- Title acceptance checked runtime title persistence/sidebar, no separate title request, manual-name preservation and reload. A local fixture supplied chat responses, so this is not an external-provider availability test.
- Search acceptance checked a built runtime's configured-default HTTP-failure fallback, unknown and empty registry boundaries, dynamic schema reload, registry privacy and browser default switching. Actual hosted-native-search failure recovery was not exercised.

See the feature guides for exact commands and prerequisites. Most browser scripts need built binaries and Playwright Chromium. Live checks depend on private existing sessions and may temporarily change state. Do not paste real tokens or passwords into logs or documentation.

## Remaining boundaries

- Anthropic and Antigravity authentication were reported working by the owner. OpenAI authorization/API transport experienced separate TLS resets and was deferred. Supporting an OAuth flow does not prove every provider completed it.
- Native Workspace and Memory HTTP surfaces remain intentionally read-only. Skills provide instructions, not extra tool permissions.
- Owner chat tools run with owner permissions. A VM or sandbox is the isolation boundary, not the tool policy or credential encryption. Provider/runtime state is not isolated for untrusted tenants.
- Vault environment bindings make secrets available to local runtime processes. Broker allowlists apply only to brokered requests, with an empty domain list unrestricted. Response scrubbing does not cover arbitrary transformed secrets from shell output.
- Voice depends on browser microphone/security permissions and configured upstream services. Live voice is ElevenLabs only. Dictation and read-aloud are turn-based and use the configured providers, and they are not guaranteed full-duplex audio.
- Remaining shared workspace edits in chat/runtime/swarm code are not automatically included in this completion record. Their owners should commit and document them independently before calling them shipped.
- Signed installers, release notarization and an update feed remain release work.
