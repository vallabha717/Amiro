A schedule runs a saved prompt on a timer, in its own timezone, and records every firing so you can see what happened. Open **Schedules** in the sidebar, or go to `/schedules`.

## Create a schedule

<Steps>
  <Step title="Open the editor">
    On the Schedules page, choose to create a new schedule.
  </Step>
  <Step title="Name and prompt">
    Give it a name and write the prompt. Write it like a message to your agent, and keep it self contained so it still makes sense on its own.
  </Step>
  <Step title="Pick a mode">
    Choose **Reminder**, **Text only**, or **Agent**. See the modes below for the difference.
  </Step>
  <Step title="Pick a cadence">
    Choose once, a recurring schedule, or an interval. For a recurring schedule you can use daily, weekdays, weekly, or monthly shapes, or type a five-field cron expression.
  </Step>
  <Step title="Set the timezone">
    Pick the IANA timezone the wall time belongs to. The preview shows the upcoming runs in that zone.
  </Step>
  <Step title="Preview and save">
    Click **Preview** to confirm the cadence, then save. A once preview returns exactly one time. A recurring or interval preview returns five upcoming runs in order.
  </Step>
</Steps>

## Modes

| Mode | Label in the editor | What it does |
| --- | --- | --- |
| Reminder | Reminder | Posts your text as-is as a thread message. No model call. |
| Text only | Text only | Runs a model turn with tools forced off and the model pinned server side. Writes a reply. |
| Agent | Agent | Runs a full agent turn with the same tool and connector access a chat has, in the agent workspace, so its home files load. |
| Script | Script | Runs a shell command in the agent's workspace and records its output. No model call. |

<Note>
A Reminder is the cheapest and most reliable option, because it never depends on the runtime. Text only and Agent pin the model you choose, so the schedule does not silently inherit a different default later.
</Note>

## Run history and controls

Open a schedule to see its detail panel and run history.

- **Run now** fires the schedule immediately, even while it is paused. A once schedule is consumed when you run it manually.
- **Pause** stops all timer firings. **Resume** brings them back.
- Each run row shows its status, output preview, and any error. Open the run's conversation to read the full result.
- The **Recent runs** view lists the latest runs across every schedule.

<AccordionGroup>
  <Accordion title="A run was skipped">
    Agent mode does not run while another runtime session is busy, for example a chat you have open. The run is recorded as skipped with a reason, and the next run stays scheduled.
  </Accordion>
  <Accordion title="A run failed">
    Failures are shown in run history with the error text. The next firing still happens on schedule.
  </Accordion>
  <Accordion title="A time does not exist">
    A wall time that never exists (the spring-forward gap) or happens twice (the fall-back fold) is rejected with an error instead of being silently shifted. Use an explicit UTC offset to pick one instant.
  </Accordion>
</AccordionGroup>

## Built-in tasks

The **Activity** tab of the Schedules page lists built-in tasks under **System tasks**:

- **Heartbeat**: the agent's periodic self-check. Its toggle and interval live in the Workspace heartbeat panel.
- **Memory upkeep**: a runtime task that is not editable.
- **Cleanup**: deletes what nobody has touched for a while. It is off until you set it up.

### Cleanup

Cleanup runs once a day without the model, so it costs nothing and takes about a second. Click **Set up** on its row to choose:

- **Untouched for**: 1, 2 or 3 days, 1 or 2 weeks, 30 days, or a custom number of hours. Something counts as touched when a message was last written in a chat, when a run finished, or when a log file was last written.
- **Time of day**: when it runs, in your timezone.
- **What to clean**: chats (including heartbeat and schedule-run chats), archived chats too, schedule run logs (the run history), and old `.log` files from Amiro and its runtime.

**Preview** lists what would go right now without deleting anything, and **Clean up now** is available after a preview. Agent channels, chats with a reply still running, run logs still in progress and the schedules themselves are always kept. Deleting can't be undone.

You can also set it up from chat in one message, for example "every night at 2 am, delete chats and logs nobody has touched for 2 days". The agent uses the built-in Cleanup instead of creating a schedule, and asks before deleting anything right away.

## Create a schedule from chat

You can also just ask, the way the video at the top does:

```text
Every weekday at 8:00 am my time, give me a morning brief: the weather in Bengaluru
today and the top 3 tech headlines from the web, each with a link. Set that up as an
agent schedule called Morning brief.
```

The agent creates the schedule through its built-in scheduling tools. It is tagged as created in chat, and the detail panel links back to the conversation it came from. If no model is given, an agent-created schedule runs on the model you last chatted with, unless the deployment sets a default.

## Templates

The **Templates** tab holds ready-made schedules that ship with Amiro: morning
briefing, meeting prep, weekly review, bills watch and more. Each one offers two
ways in:

- **Customize** opens a chat where Amiro shows the template's options as a form,
  then creates the schedule with your choices.
- **Review & add** opens the schedule form, prefilled, so you can check it and
  save it yourself.

Once you have a schedule, **Change with Amiro** in its menu or detail panel goes
back to chat to change that same schedule. The agent can see the same catalog,
so you can also just ask: "what schedule templates do you have?"

## Template: Inbox cleanup

The Schedules page features an **Inbox cleanup** template with sensible
defaults: **Keep** reservations this month and bills from the last two months;
**Clean up** promotions and unwanted notifications.

<Frame caption="The Inbox cleanup template: Customize → flip the Keep / Clean up switches → Submit → saved.">
  <video controls muted playsInline preload="metadata" poster="/docs/assets/showcase/schedules-inbox-cleanup.jpg" src="/docs/assets/showcase/schedules-inbox-cleanup.mp4" />
</Frame>

<Steps>
  <Step title="Customize">
    Click it on the template card. Amiro opens a chat and renders the rules as
    switches you can flip.
  </Step>
  <Step title="Pick your rules">
    Turn on what to keep and what to clean up, then **Submit**.
  </Step>
  <Step title="Saved">
    Amiro creates the **Inbox cleanup** schedule; it is listed under Your
    schedules, marked *Created in chat*.
  </Step>
</Steps>

<Note>
The cleanup runs against your mailbox through a connector, so connect Gmail or
Outlook first in [Connectors](/using/connectors) (Composio) before the first
run.
</Note>
