A provider is the service that actually runs the model your agent thinks with. Amiro supports many providers, but none are connected until you connect one. You connect providers as the owner, on the **Admin → Providers** page.

## Do it yourself

The steps below are exactly what the clip shows. Short on time? Type `/login` in the chat composer and follow the same panel; it never touches your transcript.

<Steps>
<Step title="Open the providers page">
Click **Admin** in the sidebar, then **Providers**. You can also type `/login` in the chat composer to open the same panel without leaving the conversation.
</Step>
<Step title="Pick your provider">
Choose the provider from the list. Each entry shows how it connects, so you can see at a glance whether it uses a key, a browser sign-in, a short code, or a local address.
</Step>
<Step title="Paste your key, or start the sign-in">
For a provider that uses a key, paste it now. If the provider signs you in instead, click the connect button and follow the browser step. Some providers also let you set an API base if they serve models from a custom address.
</Step>
<Step title="Save">
Amiro stores the secret in its encrypted credential vault. The provider flips to connected, and its models become selectable right away.
</Step>
<Step title="Pick a model">
Open the model selector in the chat composer and choose the model you want. Names are shown as `provider:model`, so it is always clear which provider a model belongs to.
</Step>
</Steps>

<Tip>
The setup chat and the providers page link straight to each provider's key page, so you do not have to hunt for it.
</Tip>

## Which path fits you

Pick the row that matches your provider. You do not need to know which one in advance: the provider's card tells you.

| If your provider gives you... | Use this path | What you need ready |
| --- | --- | --- |
| A secret string that looks like `sk-...` | **API key** | The key, copied in full, with no spaces around it |
| A website where you approve access | **OAuth (browser)** | A browser and your login on the provider's own site |
| A short code and a web address to visit | **Device code** | Any browser or phone, to enter the code |
| An address on your own machine or network | **Local endpoint** | The address where the server is listening, for example `http://localhost:8080` |

OAuth and device code both keep your provider password on the provider's own page. You never type it into Amiro.

## Verify it worked

- The provider card shows **connected**, and any key you stored shows only as a masked hint like `••••1234`, never in full.
- The model selector lists that provider's models.
- Send a short message such as "hello" and get a reply. That proves the key and the model both work end to end.
- If you connected an Anthropic, OpenAI, OpenRouter, or Gemini key, it also appears in the connection panel after a restart, because Amiro imports keys from files once per key.

## If it does not work

<AccordionGroup>
<Accordion title="The key is rejected">
- Check that you copied the whole key, with no missing characters and no extra spaces at the start or end. Most keys begin with a recognizable prefix such as `sk-`.
- Make sure the key belongs to the same provider you selected. An OpenAI key will not connect a different service.
- If you pasted the key once already and it is still rejected, remove the stored credentials and paste the key again so it is saved fresh.
</Accordion>

<Accordion title="Nothing happens after I sign in">
- Starting the sign-in is not the same as approving it. Finish the step on the provider's website, then return to Amiro.
- For OAuth, paste the callback URL or code back into the panel if Amiro asks for it.
- For a device code, enter the code at the address shown, approve access, and wait a few seconds. Amiro polls until the provider confirms, then marks the provider connected.
</Accordion>

<Accordion title="My local endpoint will not connect">
- Confirm the address is reachable from the machine running Amiro, not just from your laptop.
- Check that the model server is actually running and listening on the port you entered.
- Use the exact address the server printed at startup, including any `/v1` suffix it expects.
</Accordion>

<Accordion title="No models show up after connecting">
- Some providers list no models until their catalog loads. Reopen the providers page once.
- A provider whose usage limit is exhausted still appears as connected, but a turn against it fails with the provider's own message. That tells you it is the provider's limit and not Amiro.
- If you never pick a model, new chats use the instance default. The owner can pin a default or restrict the list to a chosen set.
</Accordion>
</AccordionGroup>

## Disconnecting or replacing a key

Open **Admin → Providers**, find the connected provider, and remove its credentials. To replace a key, remove it and connect again, or paste the new key over the old one if the provider uses keys. Disconnecting removes the stored credentials from the same place they were written, so reconnecting later is a clean start.
