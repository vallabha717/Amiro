---
title: "Credentials vault"
description: "Store API keys and tokens safely, see only masked hints, and let the agent use them without ever exposing values."
---

The credentials vault is where secrets live: API keys, tokens, and anything else the agent needs to authenticate upstream. Secrets are encrypted at rest and the list never shows values.

## Adding a credential

<Steps>
  <Step title="Open the credentials page">
    Go to Admin, Credentials.
  </Step>
  <Step title="Fill in the entry">
    Pick a service and a field, for example a GitHub token or an OpenAI key, add a label, and paste the value. The show control reveals only what you are typing.
  </Step>
  <Step title="Save">
    The value is encrypted immediately. The list shows metadata plus a masked hint, never the secret.
  </Step>
</Steps>

Quick-add buttons cover common services such as GitHub, OpenAI, gateway keys, Composio, and chat integrations. You can also add any custom service and field.

## How the agent uses secrets

The agent never sees raw values. It sees a catalog of what exists, and a server side broker injects the secret into the upstream call when needed. If you ask the agent to use a credential, it authenticates without the value entering the conversation.

## Rotating and removing

To rotate, open the entry and paste the new value over the old one. To remove, delete the entry, which also stops anything that referenced it from authenticating. Connectors that referenced the secret start reporting that they are waiting for a key instead of failing with confusing errors.

<Warning>
The vault holds the keys to your connected world. Treat the owner account as the boundary: anyone signed in as the owner can manage these entries.
</Warning>
